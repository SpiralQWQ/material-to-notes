## 三、② 边界严格（每个节点都要防呆）

在**每个交互节点**（建工作目录 / 选路 / 调零件 / 审核 / 写进度）逐类验证：**拒绝或提示，不崩溃、不卡死、不留半截**。

| 类别 | 具体样例 |
|---|---|
| 空 / 缺参 | 无输入、缺参数、参数为 None |
| 路径 | 不存在、给目录当文件、超长（>260）、中文、空格、emoji、跨盘符 |
| 权限 / 资源 | 只读目录、无权限、磁盘满、文件被占用 |
| 重复 / 并发 | 连点两次、同一工作目录并发两个实例 |
| 中断 | 中途 Ctrl-C、进程被杀、断电 |
| 状态损坏 | 状态 JSON 非法 / 半截 / 缺字段 |
| 零件异常 | 非零退出码、超时、挂死（无输出）、输出为空 |
| 网络 | 断网、超时、限流、证书错（爬取 / 模型下载） |
| 编码 | UTF-8 / 带 BOM / GBK；Windows 终端符号输出 |
| 外部依赖 | 审核 agent 限流 / 失败；模型 key 缺失 |
| 数值 / 边界 | 0 字节产物、超大文件、页码为 0、时长为 0 |

**通过标准**：每类的行为可预期（拒绝 / 提示 / 降级），**无 traceback 冒出到用户面前，无卡死，无半截产物**。

## 四、③ 终点一致性（殊途同归必须同果）

把"通向同一终点"的路径分组，**逐项**比对：状态文件 / 产物内容 / 提示文案 / 总进度单 / 退出码。任一不一致即 bug。

| 分组 | 属于该组的路径 | 必须一致的东西 |
|---|---|---|
| G-A 媒体线到笔记 | P01、P02、P03、P04、P08、P10 | 笔记结构、清洗产物形状、进度单字段与格式 |
| G-B 文档线到笔记 | P05、P06、P07、P09 | 同上 |
| G-C 停下问人 | P20、P21、P22、P23 | 提示文案格式、退出码、不产生半截产物 |
| G-D 失败交班 | P24、P25、P26、P27、P28 | 失败单**四要素齐全且格式一致**（卡在哪步 / 报什么错 / 试过什么 / 产物在哪） |
| G-E 续跑收敛 | P29、P30、P31 与其"不中断直跑"的对照 | 续跑后的产物与不中断直跑**字节级一致**（除时间戳） |

**特别检查**："直给视频（P01）" 与 "爬来的视频（P10）" 是两个入口、同一条线，终点产物与进度单必须逐项一致——这类"入口不同、终点相同"的对比是三层的重点。

## 五、执行方式

- **可自动化的**（选路、续跑、失败交班、边界、终点一致性）：用脚本 + **mock 零件**跑，快且可重复。
- **必须真跑的**（真视频转写、真 PDF 转 md、真爬取）：单独列一份**手工验证清单**，由本体触发审核 agent 走一遍。
- mock 与真跑要**共用同一套断言**，避免"mock 过了真跑崩"。

---

## 六、通过标准

1. 路径穷举：**可达率 100%**；每条可达路径功能完整、提示完整、无崩溃。
2. 边界严格：上表每一类都守住（拒绝 / 提示 / 降级），无 traceback、无卡死、无半截。
3. 终点一致性：G-A 至 G-E 每组**逐项一致**，形成《终点一致性报告》。
4. 未覆盖项（如确实无法自动化的）必须**显式登记**，不许静默跳过——**静默截断等于假装全测过**。
