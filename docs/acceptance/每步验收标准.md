> 仍标"待确认"的是**口径类**条目（如 T60 的膨胀率豁免门槛），逐条在 `docs/Task清单.md` 有编号。

## 〇、三条总则

1. **硬卡 / 软卡分开**，且**都要留证**。
   - **硬卡**：能写成脚本、只看输出就能判的（文件在不在、非空否、编码对不对、计数够不够）。由 `gates.machine`
     执行，**看原始输出判定**，不看任何 agent 的转述。
   - **软卡**：要读懂内容才能判的（语义有没有走样、是真是假、讲没讲透）。由**独立审核子 agent** 判。
2. **不采信自述**：执行方说"做完了"不算，审核方说"通过了"也不算。主对话对着**原始产物**验收。
   （2026-10-13 实测：一次审核报的 5 条里 2 条不成立，且报的行数 644 与实际的 489 不符；
   一次执行自称"未做任何改写"却做了节选。）
3. **不过就停**：单步最多尝试 3 次。3 次仍不过 → 写失败交班单、**停下问人**，不许自行改代码绕过去。

### 三条已定的口径（2026-10-13 与用户确认）

1. **穷举的范围：分层穷举**。能脚本化的**穷举**（所有数字与公式的回源核对、六件套计数、词汇表、
   元信息条目）；只能人读的**抽样**（六件套讲得实不实、类比成不成立、费曼角度是否真不同）。
   理由：机器能穷举但读不懂内容；人能读懂但读不完。
   - ⚠️ **穷举前必须先规范化**：源文的 OCR 会把数字**拆成空格分隔**（实测：源文写的是 `1. 8 5 3 2`、
     `0. 5 3 9 6`，而笔记规范成 `1.8532`）。朴素字符串比对会把这判成"笔记里有、源文里没有"的**假幻觉**。
     比对前先剥掉数字内部的空格。
2. **A 类结构项做成硬卡，但不取代软卡**：`A-1`~`A-6` 都是可数的（frontmatter 在不在、六件套是否 N/N、
   词汇表与元信息节在不在），机器判零成本、无遗漏、可回归 → **做**。但硬卡只判**齐不齐**，判不了
   **实不实**；内容仍由软卡判。**两层，不是替换。**
3. **软卡分级，不一刀切**：

   | 软卡发现 | 处置 |
   |---|---|
   | **幻觉**（源文无出处的论断/数字）或**语义保真缺失** | **阻断** —— 把假的东西教给人，性质最重 |
   | **元信息层错误**（如把某张图的 OCR 缺陷记到错的图号上） | **不阻断，但挂条件**：必须修完再交付 |
   | **风格 / 取舍分歧**（如"与前面模型衔接不紧密"） | **不阻断**，登记并浮到总进度单，经人过目 |

## 二、逐步验收标准

### 2.1 fetch（取材）

- **承诺产物**：`01_取材/**/meta.json` + 原始素材文件。
- **硬卡**：通用 H-0~H-4；**每个数据文件必须有配套 meta.json**。
- **软卡**（审核 agent 查）：
  1. meta.json 的字段是否可解析、是否与素材对得上；
  2. 有没有半截文件（`.part` / `.tmp` / `.crdownload`）；
  3. 素材内容是否与检索意图相符（有没有爬到无关页）。
- **已知陷阱**：这条线目前只支持「词汇文件 + 站点」，**不接单个网页链接**（`UNWIRED_KINDS`）。
- **状态**：适配器已写；**词汇线真跑未做**（需用户提供词汇文件与站点）。

### 2.2 document（文档转 md）

- **承诺产物**：`02_转md/<名>_mineru/full.md`（**合并后**的那一份）+ `images/` + `images_notes/`。
- **硬卡**：
  - 通用 H-0~H-4；
  - **`full.md` 必须落在 `<名>_mineru/` 根目录** —— 一本书超过 200 页会被切成 `p{start}-{end}/` 块，
    merge 之后才算完成；只有切片、没有根 `full.md` = **没做完**；
  - `full.md.bak` 必须存在且等于 **enrich 之前**的版本（原件留底绝不覆盖）。
- **软卡**：
  1. `full.md` 与源文档对得上吗（页数、章节、图片引用）；
  2. 有没有整章丢失或明显错位；
  3. `images_notes/` 里的图意是否与 `full.md` 里对应的图号相符。
- **已知陷阱**：
  - `enrich` 会**就地覆盖** `full.md`，所以快照必须在它之前；
  - 切片书的切片**原样保留**，上游契约必须只认合并后的那一份（曾一次捞到 3 份）；
  - dtmd 的 `plan.json` **跨工作目录共享**，并发跑会互相踩（T48）。

### 2.3 media（媒体转 md）

- **承诺产物**：`02_转md/{名}_clean.md`。
- **硬卡**：通用 H-0~H-4。
- **软卡**：时间轴是否连续、有无整段丢失；画面文字与语音是否对得上。
- **状态**：**2026-10-19 已真跑**（四条入口：视频 ✅ 音频 ✅ 图集 ✅ 单图 ✅）。
  实测记录见 `docs/媒体线测试计划.md` §8–§9。

**⚠️ 2.3.1 媒体线的"完整性"不能用内容门禁判（2026-10-19 实测确立）**

mre 的 `gate_check.py::extract_speech()` **只要源文里有 `🎤` 标记，就只拿语音行当对账基准，
🖼 画面文字整段丢掉**。实测 `runs/vid5`：语音行 **586** 字符 / 源文全文 **7314** 字符。

后果：**对屏幕录制型视频，"① 机械对账 100%" 和 "⑤ 膨胀率" 说明不了内容完整性**——
90 帧画面里的 IP、掩码、命令全不在基准里；膨胀率的分母只有 586 字符，涨到百分之几千也不代表注水。

**因此媒体线的验收加一条硬性要求**：

- 内容完整性**必须**由**独立审核子 agent 拿全文（语音 + 🖼 画面）做语义回源复核**判定，
  不得以门禁的 ①⑤ 过线为由放行。
- 我们这层已经把这条**印在门禁输出里**：源文是时间轴形态时，
  `gate runs/<名> note` 会在该条结果后面打出 `⚠️ …（586/7314 字符）…`。
  **看到这行警告 = 这次的门禁绿只覆盖了语音那一小部分。**
- 归属：**不是零件缺陷**（零件按"语音是作者写的、画面是 OCR 载荷"设计，
  对文档里的插图块是对的）。**暂不记回灌**，先在我们这层的验收标准里写清（用户 2026-10-19 裁定）。

### 2.4 clean（清洗）

- **承诺产物**：`03_清洗/{名}.txt`；该步统计写 `_元数据/{名}.json`（**不在交付目录里**，见架构契约 §五）。
- **硬卡**：
  - 通用 H-0~H-4；
  - **保真门禁** `validate.structure_loss()`：**行数 / 标题 / 公式 `$$` / 表格 `<td` / 代码围栏**五类标记，
    上游存在而下游留存 **< 90%** 即判本步失败。**`--deep-clean` 不豁免**；
  - `_元数据/{名}.json` 的 stats **不得**包含 `cleaned_text`（tce 会回显全文，照抄等于把文档存两遍）；
  - 有结构损失时，`_元数据/{名}.json` 必须带 `structure_lost` 字段写明掉了哪几类。
- **软卡**：清洗前后内容量是否骤降；有没有把教学内容一起洗掉。
- **已知陷阱**：全规则清洗（trafilatura 网关）会把 28 页论文压成 1 行、表格清零——**默认只剥水印**。

### 2.5 note（写笔记）—— 最关键的一步，见第三节

- **承诺产物**：**每份素材一个** `04_笔记/<显示名>.md`。
- **硬卡**：
  - 通用 H-0~H-2（`pipeline gate … note`）；
  - `gates/content.py`：frontmatter（8 字段与顺序）/ 一句话总结 / 概述 / 核心知识点 / 专业词汇表 / 自测题 / 元信息，
    外加"知识点必须是零件形状、且不能是 0 个"；
  - **内容门禁**：mre 的 `scripts/gate_check.py <该份笔记> --src <它自己那份原文>` ——
    ① 机械对账（数字覆盖率 ≥90%）② 六件套齐 ③ 费曼每点 ≥2 ④ 膨胀率；
    **禁用 `--score`**（第三方 GLM 评分，已由审核 subagent 取代）。**每份都要跑**；
  - **素材是媒体（时间轴形态）时，①⑤ 另算**：见 §2.3.1 —— 那两项只覆盖语音行，
    **完整性必须另做全文语义复核**，不得以门禁过线放行；
  - **每份素材都要有自己的笔记**（`note-every-material-covered`）。缺的那份**不在场上**，
    没有别的检查会问它该不该在——实测两份素材只写出一份时，其余全 PASS。
  - `04_笔记/` 中**对不上素材的 `.md` 判失败**（`note-no-orphans`，改名孤儿）。
- **软卡**：见第三节逐条。

## 三、最终交付物的验收标准（`note.md`，详细穷举）

> 这是整条线的**终点**，也是用户最看重的一份。以下条目**逐条独立判定**，
> 每条都必须给出**可指证据**（笔记行号 + 源文行号）。任一条判"不通过"都要写进结论。

### A. 结构完整性（硬性，可脚本判）

| 编号 | 判据 | 证据形式 |
|---|---|---|
| A-1 | **frontmatter 按零件规范的 8 个字段、顺序固定**：`title` / `source` / `author` / `duration` / `word_count` / `created` / `tags` / `type`（OKF 增强字段可续在其后） | frontmatter 原文 |
| A-2 | **正文 7 栏目齐全**：`> 一句话总结：…` / `📚 概述` / `📑 本篇目录` / `🧠 核心知识点` / `📖 专业词汇表` / `❓ 自测题` / `📌 元信息` | 各栏目标题 |

> **A-2 的两条口径（2026-10-15 定，此前"7 栏 vs 规范 8 项"一直说不清）**：
> ① **为什么是 7 栏**：规范的 `structure:` 列 8 项，多出来的第 7 项 `transcript`（完整转写附录）
> 按规范自己的 `appendix: full_original_external` **外置**到 `_元数据/照录/`，**正文不放**，所以正文是 7 栏。
> ② **第 6 栏叫什么**：规范的注释写 `❓ 费曼思考题`，我们已入库的 7 份笔记写 `❓ 自测题`——
> **两者门禁都认**（`gates/content.py::_SECTIONS` 的别名表含 `自测题/费曼思考题/费曼题`）。
> 本项目统一叫 **`❓ 自测题`**（保持与既有笔记一致）；派活单里的这个标题由
> `orchestrate/spec.py::_COLUMN_HEADING` 给出，改规范不会让两边再对不上。
> ③ **`📑 本篇目录` 门禁不单独查**（`gates/content.py` 有意跳过：它由 `pipeline toc` 用零件脚本后处理生成），
> 但 SOP 第二节把 `pipeline toc` 列为 note 步的固定动作，所以它**流程上必在、门禁上不判**。
| A-3 | 每个知识点写成 **`### 知识点 N.M · <标题>`**（零件门禁能解析的形状），六件套齐全：定义 / 类比 / 原理 / 示例 / 为什么 / 易错点，**各写成粗体标签行** | 门禁原始输出 |
| A-4 | 专业词汇表存在，**只收源文出现过的术语** | 术语表原文 + 逐个回源核对 |
| A-5 | **费曼示范写在知识点内部**（第七项 `- **❓ 示范角度**：`），每点 **2–4 个角度**且角度确实不同（复述 / 类比 / 应用 / 挑错，不是同句改写）。**角度是「线索」不是「讲解」**——规范原话是"教学留白：给 AI 考察线索，AI 可自行展开，**不写满教学稿**"；每条一两句即可，**不许复述** `通俗类比` / `原理` / `易错点` 已讲过的话 | 门禁原始输出 + 抽查 2 处全文 |
| A-6 | 文末「`📌 元信息`」一节存在（源文自身问题只登记在这里，**不进正文**） | 元信息原文 |
| A-7 | **正文长度上限 800 行 / 5.5 万字符**（2026-10-15 用户拍板，按 `AI教材笔记库` 75 份真实笔记的中位校准：796 行 / 5.26 万字符）。计量范围＝教学内容本体，**不含** `📖 专业词汇表` / `📌 元信息` / 附录（它们不是拿来讲的，是拿来查的）。**超限才拆册**：按知识点簇拆（每册 5–8 个知识点）＋一册索引（一句话总结 + 各册链接）＋分册互链 `[[目标#锚点\|显示文本]]`，并在各册 frontmatter 填 `prerequisites` / `next` / `related` | 各册的正文行数与字符数 + 索引册原文 |

> **A-7 的生效条件**（2026-10-15 用户定，二者齐了才开卡）：
> ① **Task-14 落地后**（"对账照录"从交付物分流出去——现在长的主因是它）；
> ② **Task-23 落地后**（流程支持"一份素材 → 1..N 册 + 索引"：投料单、门禁、交付都要认这个形状）。
> 在两者完成前，A-7 **只作为标准存在、不进机器门禁**——否则长笔记会被判 FAIL 却无路可走。
> 400 这个数**还要用实测校准**（拿现有 5 份 + 已入库的 13 组 / 24 章笔记量一遍），校准结果若与 400 冲突，回来找用户改数。
>
> **2026-10-15 实测校准结果**（Task-14 分流之后，量的都是"教学内容本体"）：
> 我们这 7 份的正文 = **171–301 行 / 1.8 万–5.7 万字符**；而 `AI教材笔记库` 75 份真实笔记的中位是
> **796 行 / 5.26 万字符**（最大 2931 行 / 17.5 万字符）。
> **冲突点在字符那一侧**：3 份超 4 万字符（4.3 / 4.5 / 5.7 万）。
> **我的建议**（待用户拍板）：阈值按既有习惯校准为 **≤800 行 / ≤5.5 万字符**——现在 7 份全部达标，
> 且**不必做拆册**（Task-23 可暂缓）。用户没点头之前，**A-7 仍按 400 行 / 4 万字符记，且不进机器门禁**。

> **A 组的形状由零件定，不由我们定**：以上字段名、栏目、标题形状都出自
> `parts/md-rewrite-engine/src/md_rewrite_engine/configs/note_style_spec.yaml`（v1.3）。我们只**核对**，不另立标准。

### B. 内容保真（软性，逐点核）

| 编号 | 判据 | 证据形式 |
|---|---|---|
| B-1 | **语义保真**：抽 **≥5 个关键事实点**（数字 / 公式 / 结论 / 算法步骤）对照源文逐点核，不得改写、算错、丢失 | 每个点：笔记行号 ↔ 源文行号 |
| B-2 | **机械对账**（数字覆盖率 ≥90%）过线，**未过线的缺口必须逐个给出解释**（如确属 OCR 噪声） | 门禁原始输出 + 缺口解释 |
| B-3 | **公式编号与源文一致**（式 9/10/15/16/18/20 这类） | 逐个对照 |
| B-4 | **图表内容进入正文**：源文 `full.md` 里被引用的插图，其图意必须能在笔记里找到对应叙述 | 插图数 ↔ 笔记引用数 |
| B-5 | **术语与数字原样保留**（英文术语、变量名、单位、量级不得擅自换算） | 抽查 ≥5 处 |

### C. 无幻觉（软性，逐点找源）

| 编号 | 判据 | 证据形式 |
|---|---|---|
| C-1 | **抽 ≥5 个事实点在源文里找出处**；找不到出处即问题 | 每个点：笔记行号 → 源文行号 |
| C-2 | 任何**源文没有**的数字、结论、方法名，若为讲解需要而添加，**必须标注**「（源文未述，此处为讲解补充/举例）」 | 全库检索该数字 + 标注是否存在 |
| C-3 | **不得添加源文没有的论断**（"通常做法""一般来说"这类未经标注的补充） | 抽查 |

### D. 教学可用性与体量（软性）

| 编号 | 判据 | 证据形式 |
|---|---|---|
| D-1 | **六件套不是空壳**：抽 ≥3 个知识点，各读一项全文，判断类比是否成立、示例是否真在讲那个知识点 | 抽查段落原文 |
